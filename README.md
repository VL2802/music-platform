# Music Platform

Music Platform is an ASP.NET Core Razor Pages application for managing and
exploring a personal media library. It supports songs, audiobooks, collections,
playlists, user accounts, role-based access, and password reset workflows.

## Features

- Register and authenticate users with cookie-based sessions.
- Support listener and artist roles with authorization policies.
- Browse songs and audiobook chapters.
- Create and manage artist collections and playlists.
- Manage media files stored under the web application's static content.
- Validate users, collections, and media through a separate logic layer.
- Generate and consume password-reset tokens.

## Technology

- C# and .NET 8
- ASP.NET Core Razor Pages
- ADO.NET with SQL Server stored procedures
- Cookie authentication and ASP.NET Core authorization
- xUnit-based tests
- Bootstrap and jQuery validation assets

## Architecture

The solution is divided into four application projects:

- `SharedLibraryML`: shared domain models, enums, and repository interfaces.
- `ML_DAL`: SQL Server repositories and data-access strategies.
- `ML_LogicLayer`: services, validation, authorization, and password-reset logic.
- `ML_WebApp`: ASP.NET Core Razor Pages UI, dependency injection, and web services.

The web application resolves a SQL Server connection string from configuration
and passes it to the data-access layer. Authentication and authorization are
handled by ASP.NET Core middleware, while business rules remain in the logic
layer.

## Requirements

- .NET 8 SDK
- Access to a compatible SQL Server database with the required stored procedures
- A development certificate for local HTTPS, generated by the .NET SDK

## Configuration

The committed `Application/ML_WebApp/appsettings.json` intentionally contains no
credential. Set the connection string through the environment variable
`ConnectionStrings__DefaultConnection` before running the application:

```powershell
$env:ConnectionStrings__DefaultConnection = "Server=localhost;Database=musiclibrary;User Id=musicapp;Password=<local-password>;TrustServerCertificate=true;"
```

Do not commit passwords, tokens, private media, or local configuration files.
`appsettings.Development.json` enables detailed errors for local development
only; use less verbose error handling in a deployed environment.

## Run locally

```powershell
cd Application
dotnet restore ML.sln
$env:ConnectionStrings__DefaultConnection = "Server=localhost;Database=musiclibrary;User Id=musicapp;Password=<local-password>;TrustServerCertificate=true;"
dotnet run --project ML_WebApp\ML_WebApp.csproj
```

Open the HTTPS URL printed by the application. The database schema and stored
procedures are not included in this repository, so they must be provisioned
separately.

### Database setup

1. Create a SQL Server database such as `musiclibrary`.
2. Create a database login/user with only the permissions required by the
   application.
3. Apply the project's schema for users, media, collections, collection-media
   relationships, and password-reset tokens.
4. Create the stored procedures used by the repositories, including
   `sp_CreateUser`, `sp_UpdateUser`, `sp_DeleteUser`, `sp_ReadAllUsers`,
   `sp_FindUserByEmail`, and `sp_ReadUser`, plus the media and collection
   procedures referenced under `Application/ML_DAL`.
5. Set `ConnectionStrings__DefaultConnection` and run the application.

No SQL schema or stored-procedure scripts were found in this repository, so a
database administrator must supply or create these objects before the first run.
